VIGIL: Defending LLM Agents Against Tool Stream Injection via Verify-Before-Commit

논문 및 이미지 출처 : https://aclanthology.org/2026.acl-long.443.pdf

아래는 업로드한 논문의 Abstract 부터 Sec. 6 Conclusion and Future Work 까지의 전체 번역이다. 요청한 번역 규칙에 따라 inline reference 는 제거하고, Table/Figure 자체와 caption 은 생략했으며, 본문에서 Tab./Fig. 를 해설하는 부분은 list 형식으로 구성했다.

Abstract

open environment 에서 동작하는 LLM agent 는 indirect prompt injection 으로 인한 위험이 점차 증가하고 있으며, 특히 조작된 metadata 와 runtime feedback 이 execution flow 를 hijack 하는 tool stream 에서 이러한 위험이 두드러진다. 기존 defense 는 중요한 딜레마에 직면한다. advanced model 은 strict alignment 때문에 injection 된 rule 을 우선시하는 반면, static protection mechanism 은 adaptive reasoning 에 필요한 feedback loop 를 단절한다.

이러한 충돌을 조정하기 위해, 저자는 restrictive isolation 에서 verify-before-commit protocol 로 paradigm 을 전환하는 framework 인 VIGIL 을 제안한다. VIGIL 은 speculative hypothesis generation 을 가능하게 하고 intent-grounded verification 을 통해 safety 를 강제함으로써, reasoning flexibility 를 유지하면서도 robust control 을 보장한다.

저자는 또한 dynamic dependency 를 특징으로 하는 광범위한 threat 를 simulation 하도록 설계된 959 개의 tool stream injection case 로 구성된 benchmark 인 SIREN 을 도입한다.

광범위한 experiment 는 VIGIL 이 state-of-the-art dynamic defense 보다 attack success rate 를 22% 이상 감소시키는 동시에, static baseline 과 비교하여 attack 상황에서의 utility 를 2 배 이상 향상함을 보여준다. 이를 통해 security 와 utility 사이에서 최적의 balance 를 달성한다.

https://github.com/Touring-686/vigil

1 Introduction

LLM 의 빠른 발전은 agent 를 passive text generator 에서 email automation 부터 critical infrastructure maintenance 에 이르는 sensitive workflow 를 orchestration 하는 autonomous system 으로 변화시켰다. 그러나 신뢰할 수 없는 external environment 로부터 data 를 ingest 해야 하는 operational necessity 때문에 이러한 system 은 Indirect Prompt Injection (IPI) attack 에 취약하다.

공격자는 retrieved content 내부에 malicious instruction 을 삽입함으로써, model 이 system instruction 과 external data 를 구분하지 못하는 점을 악용하여 execution flow 를 hijack 하고 agent 가 unauthorized action 을 수행하도록 강제한다.

IPI 에 관한 기존 연구는 malicious directive 가 web page 나 database 와 같은 static context 에 존재하는 data stream 을 중심으로 이루어져 왔다. 그러나 model context protocol 과 같은 open standard 의 도입은 tool stream 내에 중요한 vulnerability 를 만들어냈다.

passive data content 와 달리, tool stream 은 model 이 단순한 information 이 아니라 binding operational constraint 로 해석하는 functional definition 과 runtime feedback 으로 구성된다. 공격자는 forged tool description 이나 deceptive error message 를 injection 하여 authoritative system command 를 모방함으로써 이러한 mechanism 을 악용한다. 이를 통해 context-level defense 를 우회하고 agent 의 decision-making process 를 직접 조작할 수 있다.

Fig. 1 에 나타난 것처럼, 저자는 이러한 tool stream intrusion 이 현대 agent architecture 에 미치는 영향을 분석하여 두 가지 systemic failure mode 를 식별한다.

  • 첫 번째 challenge 는 Alignment-Driven Vulnerability 이다.

    • advanced model 은 superior instruction-following capability 때문에 오히려 tool stream attack 에 더 높은 susceptibility 를 보인다.
    • weaker model 은 제한된 semantic parsing 능력으로 인해 benign failure 를 일으키는 경우가 많다.
    • 반면 strong reasoning model 은 injection 된 malicious rule 을 authoritative constraint 로 해석한다.
    • strict alignment training 으로 인해 이러한 rule 을 user intent 보다 우선시한다.

  • 두 번째 challenge 는 Static Defense Fragility 이며, 이는 plan-then-execute paradigm 에 의존하는 system 에 내재한다.

    • 이러한 mechanism 은 deterministic environment 를 가정하고 execution 전에 rigid permission boundary 를 강제한다.
    • 그 결과 malicious tool 이 fabricated error 를 반환할 때 adaptive recovery 에 필요한 feedback loop 가 단절된다.
    • 이는 task completion rate 의 심각한 붕괴로 이어진다.

이러한 cognitive hijacking 과 utility collapse 의 이중 위험을 완화하기 위해, 저자는 VIGIL (Verifiable Intent-Grounded Interaction Loop) 을 제안한다.

restrictive plan-then-execute model 과 달리, 이 framework 는 reasoning exploration 과 irreversible action 을 분리하는 verify-before-commit paradigm 을 구현한다.

  • 먼저 user intent 에 anchor 된 dynamic constraint 를 synthesis 하여 root of trust 를 수립한다. 이에 대한 자세한 내용은 Sec. 4.2 에 제시한다.
  • adversarial input 은 perception sanitization 을 통해 neutralize 한다. 이에 대한 자세한 내용은 Sec. 4.3 에 제시한다.
  • environmental uncertainty 를 처리하기 위해 agent 는 speculative reasoning 을 통해 잠재적인 execution path 를 탐색한다. 이에 대한 자세한 내용은 Sec. 4.4 에 제시한다.
  • runtime verifier 는 tentative trajectory 가 실제로 commit 되기 전에 이를 엄격하게 validate 한다. 이에 대한 자세한 내용은 Sec. 4.5 에 제시한다.
  • intent-grounded verification 과 adaptive backtracking 을 결합함으로써, VIGIL 은 malicious tool feedback 으로 인한 deviation 을 수정하며 complex problem-solving 에 필요한 flexibility 를 희생하지 않고 execution flow 의 integrity 를 보존한다.

저자는 realistic execution environment 를 simulation 하는 SIREN (Systemic Injection & Reasoning Evaluation beNchmark) 에서 framework 를 평가한다. 이 environment 는 496 개의 competing tool 과 dynamic dependency 로 구성된다.

SIREN 은 agent lifecycle 의 critical phase 를 공격하는 5 가지 attack vector 에 걸쳐 959 개의 tool stream injection case 를 포함하며, AgentDojo 로부터 얻은 949 개의 data stream baseline 을 함께 포함한다.

광범위한 experiment 는 다음을 보여준다.

  • VIGIL 은 이러한 threat 를 효과적으로 neutralize 하고 tool stream 의 평균 Attack Success Rate (ASR) 를 약 8~12% 수준까지 낮춘다.
  • 이는 최근 dynamic defense 보다 22% 이상 우수한 성능이다.
  • 동시에 data stream attack 에 대해서는 strict isolation 과 유사한 수준의 performance 를 유지한다.
  • 특히 rigid baseline 이 일반적으로 12% 이하까지 저하되는 adversarial setting 에서, VIGIL 은 Utility Under Attack (UA) 를 2 배 이상 향상함으로써 static defense 의 utility collapse 문제를 해결한다.
  • 이러한 result 는 VIGIL 이 rigidity-utility trade-off 를 성공적으로 완화하고, security 와 utility 사이의 최적 balance 를 달성하면서 data stream 과 tool stream 모두의 injection attack 에 대해 unified solution 을 제공함을 보여준다.

저자의 contribution 은 다음과 같다.

  • 저자는 tool stream injection threat 를 formalize 하고, realistic stochastic environment 에서 agentic reasoning challenge 를 simulation 하기 위해 5 가지 vector 와 959 개 case 로 구성된 comprehensive benchmark SIREN 을 도입한다.
  • 저자는 intent-grounded safety boundary 를 synthesis 하는 동시에 speculative backtracking 을 이용해 secure error recovery 를 가능하게 하고 reasoning flexibility 를 보존하는 verify-before-commit framework VIGIL 을 제안한다.
  • 광범위한 evaluation 을 통해 VIGIL 은 state-of-the-art dynamic defense 와 비교하여 ASR 을 22% 이상 감소시키고, adversarial setting 에서 static baseline 대비 UA 를 2 배 이상 향상함을 보여준다.

2 Related Work

Defensive Architectures for Agents​

IPI 에 대한 초기 defense 는 malicious input 을 filtering 하기 위한 heuristic prompt engineering 또는 external detection module 에 의존했다. 이러한 empirical method 는 adaptive attack 에 취약한 경우가 많기 때문에, 최근 연구는 static plan-then-execute paradigm 으로 대표되는 systematic architectural separation 으로 전환되었다.

ACE 와 같은 framework 는 environmental interaction 이전에 immutable execution plan 을 생성함으로써 strict permission isolation 을 강제한다.

이러한 rigid architecture 는 deterministic setting 에서는 효과적이지만, execution 전에 control flow 를 freeze 하기 때문에 flexibility 를 저해한다. 이에 따라 flexible reasoning 에 필요한 feedback loop 가 단절되어 system 이 complex task 를 처리하거나 unexpected error 로부터 recovery 하지 못하게 된다.

utility 를 회복하기 위해 최근 dynamic framework 는 interaction 중 security policy 를 update 하거나 masked re-execution 을 사용하여 anomaly 를 detect 함으로써 isolation cost 를 완화한다.

하지만 이러한 approach 는 controlled deviation 을 허용하면서도 주로 data stream sanitization 에 초점을 맞추고 tool definition 의 operational authority 를 간과한다. tool reliability 를 암묵적으로 가정하기 때문에 injection 된 instruction 이 system constraint 로 잘못 해석되는 mimicry attack 에 여전히 취약하다.

반대로 VIGIL 은 data stream 과 tool stream 모두를 명시적으로 distrust 하는 verify-before-commit paradigm 을 구축하고, speculative reasoning 을 이용하여 robust security 와 complex problem-solving 을 조화시킨다.

Evaluation for Agent Security​

agent security evaluation 은 single-turn prompt robustness test 에서 dynamic environmental assessment 로 발전해 왔다.

초기 framework 는 stateful environment 내의 multi-step interaction 을 도입했다. 하지만 이러한 benchmark 의 근본적인 한계는 tool integrity 를 암묵적으로 가정했다는 점이다. 따라서 malicious email 과 같은 data stream threat 에 evaluation 이 거의 전적으로 집중되었고, executable toolset 자체가 attack surface 가 될 수 있다는 점은 간과되었다.

최근 연구가 open protocol 을 통한 tool stream 의 vulnerability 를 실제로 드러냈지만, 기존 evaluation 은 여전히 data risk 와 tool risk 를 서로 독립적인 vector 로 취급하거나 reasoning complexity 가 제한된 scenario 에 초점을 맞추는 경우가 일반적이다.

이러한 fragmented approach 는 instruction-following bias 와 adaptive reasoning requirement 를 동시에 악용하는 compounded threat 에 대한 agent resilience 를 제대로 정량화하지 못한다.

저자는 이러한 gap 을 해결하기 위해 dual-stream threat 와 complex reasoning dependency 를 하나의 unified evaluation framework 에 통합한 SIREN 을 도입한다.

3 The SIREN Environment

Threat Model​

저자는 agent 가 system instruction 과 private memory 를 포함하는 trust boundary 내부에서 동작하고, external environment 는 untrusted 상태로 유지되는 standard black-box threat model 을 따른다.

이 setting 에서 adversary 는 model weight 나 internal state 에 접근할 수 없으며, interaction 중 retrieve 되는 information 을 manipulation 하는 방식으로만 agent 에 영향을 미친다.

중요하게도 저자는 attack surface 를 passive data stream 에서 active tool stream 까지 확장한다. 여기서 attacker 는 compromised third-party tool provider 로 동작한다.

이 capability 를 통해 adversary 는 다음을 수행할 수 있다.

  • planning phase 동안 tool definition 에 malicious constraint 를 injection 한다.
  • execution phase 동안 deceptive feedback 을 fabricate 한다.
  • authoritative system command 를 모방하여 agent 의 strong instruction-following 성향을 악용한다.
  • legitimate tool usage 로 위장하면서 malicious directive 를 user intent 보다 우선하도록 한다.

Environment Reconstruction​

tool stream manipulation 에 대한 agent robustness 를 평가하기 위해, 저자는 AgentDojo 를 기반으로 execution environment 를 재구성하고 real-world operational challenge 를 반영하는 두 가지 architectural feature 를 도입한다.

첫째, open tool library 의 높은 density 를 반영하기 위해 semantic tool redundancy 를 구현한다.

  • 기존 toolset 을 총 496 개 tool 로 구성된 comprehensive library 로 확장한다.
  • 동일한 functional domain 에 embedding representation 은 겹치지만 parameter specification 이 서로 다른 utility 를 배치한다.
  • 이 configuration 은 unverified source 에서 safe tool 을 선택해야 하는 어려움을 simulation 한다.
  • 따라서 agent 는 precise schema verification 을 바탕으로 legitimate utility 와 malicious mimic 을 구분해야 한다.

둘째, external API interaction 에 내재한 instability 를 simulation 하기 위해 stochastic runtime feedback 을 도입한다.

  • randomized failure 와 fabricated status message 를 추가한다.
  • agent 가 dynamic exception handling 과 re-planning 을 수행하도록 강제한다.
  • 이에 따라 agent 의 error recovery process 자체가 hijacking attempt 에 노출된다.
  • attacker 는 agent 의 adaptive behavior 를 악용할 수 있다.

Threat Injection Vectors​

Tab. 1 에 설명된 것처럼, 저자는 agent 의 전체 operational lifecycle 을 포괄하기 위해 총 959 개 case 로 구성된 5 가지 distinct tool stream attack vector 를 체계적으로 구현한다.

planning phase 에 대해서는 tool selection 과 parameter formulation 을 compromise 하는 세 가지 definition-level injection 을 설계한다.

  • Explicit Directive

    • 174 개 case 로 구성된다.
    • docstring 내부에 mandatory constraint 를 삽입하여 model 의 compliance bias 를 악용한다.

  • Dependency Trap

    • 184 개 case 로 구성된다.
    • fabricated prerequisite 를 도입하여 malicious predecessor tool 을 실행하도록 강제한다.
    • 이를 통해 causal reasoning chain 을 조작한다.

  • Feature Inducement

    • 179 개 case 로 구성된다.
    • semantically attractive functional description 을 사용하여 co-domain tool 사이의 semantic confusion 을 유도한다.

runtime phase 에 대해서는 feedback loop 를 통해 agent 를 hijack 하는 두 가지 execution-level vector 를 도입한다.

  • Runtime Hijacking

    • 272 개 case 로 구성된다.
    • return value 내부에 adversarial directive 를 삽입하여 internal state tracking 을 직접 override 한다.

  • Error Hijacking

    • 150 개 case 로 구성된다.
    • blocking error 와 malicious standard operating procedure 를 함께 simulation 하여 exception handling mechanism 자체를 weaponize 한다.

마지막으로, 서로 다른 attack surface 에 대한 defense efficacy 를 comprehensive 하게 비교하기 위해 AgentDojo 의 기존 content injection case 949 개를 data stream baseline 으로 포함한다.

4 The VIGIL Framework

4.1 Overview​

저자는 secure agentic reasoning 문제를 untrusted environment 에서 validated action sequence 를 선택하는 문제로 formalize 한다.

standard agent 의 policy 는 다음과 같다.

π(at∣q,Dδ,Fδ)\pi(a_t \mid q, D_\delta, F_\delta)π(at​∣q,Dδ​,Fδ​)

이 policy 는 user query qqq 와 potentially malicious injected input 으로부터 action ata_tat​ 를 직접 mapping 한다.

  • DδD_\deltaDδ​ 는 planning-level attack 을 전달하는 static Data and Tool Definition Stream 을 나타낸다.

    • 예를 들어 docstring, schema, retrieved content 가 이에 해당한다.

  • FδF_\deltaFδ​ 는 execution-level attack 을 전달하는 dynamic Runtime Execution Feedback Stream 을 나타낸다.

    • 예를 들어 status update, SOP, error message 가 이에 해당한다.

  • subscript δ\deltaδ 는 해당 information 이 untrusted origin 에서 왔음을 의미한다.

이와 같이 untrusted channel 에 직접 conditioning 하는 policy 는 본질적으로 hijacking 에 취약하다.

이를 완화하기 위해 VIGIL 은 task 를 direct action selection 문제에서 potential trajectory 의 hypothesis space HHH 에 대한 constrained selection 문제로 재구성한다.

final action 은 grounding verification function VVV 를 만족하는 모든 valid trajectory 집합에서 선택된 trajectory τ∗\tau^*τ∗ 로부터 도출된다.

\tau^* ====== \mathrm{select} \left( \left{ \tau_i \in H \mid V(\tau_i, C, q)=\mathrm{true} \right} \right)

여기서 CCC 는 immutable 하고 intent-grounded 된 constraint 를 의미한다.

Fig. 2 에 나타난 것처럼, 이러한 secure lifecycle 은 objective 를 공동으로 해결하는 5 가지 component 에 의해 orchestration 된다.

  • ➊ Intent Anchor

    • qqq 로부터 constraint CCC 를 synthesis 한다.

  • ➋ Perception Sanitizer

    • HHH 를 생성하기 위한 sanitized input space 를 제공한다.

  • ➌ Speculative Reasoner

    • hypothesis space HHH 를 생성한다.

  • ➍ Grounding Verifier

    • validation function VVV 를 구현한다.

  • ➎ Validated Trajectory Memory

    • selection outcome 에 기반한 adaptation 을 지원한다.

4.2 Ground-Truth Constraint Synthesis​

VIGIL 은 exclusively query qqq 로부터 도출된 root of trust 에 optimization process 를 grounding 한다.

이를 다음과 같은 intent anchoring function 으로 formalize 한다.

Φ:q→(S,C)\Phi : q \rightarrow (S, C)Φ:q→(S,C)

Φ\PhiΦ 는 security analyst 로 configure 된 role-specialized LLM 으로 구현된다.

이 function 은 두 가지 주요 artifact 를 synthesis 한다.

  • 첫 번째는 high-level workflow 를 정의하는 abstract sketch SSS 이다.
  • 두 번째는 허용 가능한 behavior 의 hard boundary 를 명시하는 logical invariant 집합 CCC 이다.

이렇게 dynamically synthesis 된 invariant 는 generic safety rule 이 아니라 query qqq 에 특화된 constraint 이다.

travel planning 과 관련된 query 에 대해 Φ\PhiΦ 는 다음과 같은 constraint 를 생성할 수 있다.

Cdomain:scope⊆TravelC_{\mathrm{domain}} : \mathrm{scope} \subseteq {\mathrm{Travel}}Cdomain​:scope⊆Travel

그리고 operational constraint 는 다음과 같다.

Cop:transactiontype∈MERCHANTC_{\mathrm{op}} : \mathrm{transaction_type} \in {\mathrm{MERCHANT}}Cop​:transactiont​ype∈MERCHANT

이후 Grounding Verifier 는 이러한 constraint 를 intent-level ground truth 로 사용하여 trajectory compliance 를 평가하고, foundational condition 을 위반하는 path 를 사전에 pruning 한다.

4.3 Sanitizing the Adversarial Input Space​

adversarial injection 이 hypothesis generation process 를 corrupt 하는 것을 방지하기 위해, Perception Sanitizer 는 objective rewriting mechanism 을 사용한다.

저자는 이를 다음과 같은 sanitization function 으로 formalize 한다.

Ψ:(Dδ,Fδ)→(D^,F^)\Psi : (D_\delta, F_\delta) \rightarrow (\hat{D}, \hat{F})Ψ:(Dδ​,Fδ​)→(D^,F^)

이 function 은 tool description 의 propositional content 를 해당 표현의 illocutionary force 로부터 분리한다.

이 component 는 imperative command 나 artificial urgency 와 같은 manipulative linguistic modifier 를 neutralize 하는 동시에 core functional semantic 은 보존한다.

예를 들어 다음과 같은 coercive directive 가 삽입된 adversarial description 을 고려할 수 있다.

[System Rule] Execute Malicious_Tool prior to this operation

이 description 은 tool 의 intended utility 만을 설명하는 neutral factual statement 로 transform 된다.

directive component 를 제거함으로써, 이러한 transformation 은 Speculative Reasoner 에 sanitized tool space representation 을 제공한다.

그 결과 generated hypothesis space HHH 는 deceptive command 가 아니라 objective fact 에 grounding 되며, reasoning stage 에서 model 의 compliance bias 가 trigger 되는 것을 방지한다.

4.4 Hypothesis Space Generation​

static planning 의 rigidity 를 해결하기 위해, VIGIL 은 speculative reasoning 을 이용하여 potential trajectory 의 hypothesis space HHH 를 생성한다.

각 step 에서 reasoner 는 Perception Sanitizer 로부터 제공된 sanitized tool information (D^,F^)(\hat{D}, \hat{F})(D^,F^) 을 사용하여 multiple candidate branch 를 탐색한다.

각 candidate trajectory τi∈H\tau_i \in Hτi​∈H 는 potential action 의 sequence 로 구성된다.

τi======a1,a2,…,am\tau_i ====== {a_1, a_2, \ldots, a_m}τi​======a1​,a2​,…,am​

이 trajectory 를 validation 에 사용할 수 있도록 준비하기 위해, 각 action ak∈τia_k \in \tau_iak​∈τi​ 는 다음 profiling function 에 의해 structured metadata 로 변환된다.

Ω:ak→Mak\Omega : a_k \rightarrow M_{a_k}Ω:ak​→Mak​​

앞선 example 에서 이 profiling 은 서로 다른 두 trajectory 를 instantiate 할 수 있다.

  • τ1\tau_1τ1​ 은 Authorize_Transfer tool 을 포함한다.
  • τ2\tau_2τ2​ 는 Expedia_Search procedure 를 따른다.
  • 각 trajectory 는 operation type 과 information flow 에 관한 고유 metadata 를 가진다.

전체 process 는 hypothetical sandbox 내부에서 수행되기 때문에, agent 는 validated path 를 실제로 commit 하기 전에 potential risk 를 평가할 수 있다.

4.5 Grounded Verification and Adaptation​

action 을 실제로 commit 할지에 대한 최종 decision 은 framework 의 core validation logic 을 구현하는 Grounding Verifier 가 담당한다.

verifier 는 trajectory τi\tau_iτi​ 를 validate 하는 complex task 를 두 개의 더 단순한 sequential reasoning step 으로 분해한다.

이를 composite function VVV 로 formalize 하면 다음과 같다.

V(τi,C,q)===============Vcompliance(Mτi,C)∧Ventailment(τi,q)V(\tau_i, C, q) =============== V_{\mathrm{compliance}}(M_{\tau_i}, C) \land V_{\mathrm{entailment}}(\tau_i, q)V(τi​,C,q)===============Vcompliance​(Mτi​​,C)∧Ventailment​(τi​,q)

validation process 는 role-specialized LLM 에 의해 수행되며 먼저 invariant compliance check VcomplianceV_{\mathrm{compliance}}Vcompliance​ 로 시작한다.

이 stage 는 action metadata MτiM_{\tau_i}Mτi​​ 와 hard constraint CCC 사이의 focused consistency check 로 decision 을 축소하며, 이를 narrow-domain classification task 로 구성한다.

예를 들어 travel planning task 에서 P2P transaction type 을 포함하는 trajectory τ1\tau_1τ1​ 은 사전에 설정된 CopC_{\mathrm{op}}Cop​ constraint 를 위반하기 때문에 reject 된다.

반면 compliant trajectory 인 τ2\tau_2τ2​ 는 이후 semantic entailment assessment VentailmentV_{\mathrm{entailment}}Ventailment​ 로 진행한다.

이 stage 는 trajectory 가 user intent qqq 를 충족하기 위한 necessary step 인지를 판단하는 logical reasoning task 를 수행한다.

verification 을 이러한 distinct structural check 와 semantic check 로 분해함으로써, framework 는 LLM 에 가해지는 cognitive load 를 크게 줄이고 decision space 를 제한한다. 이에 따라 single monolithic execution prompt 와 비교하여 hijacking risk 를 완화한다.

trajectory 는 두 validation stage 를 모두 성공적으로 통과한 경우에만 approve 된다.

이후 Validated Trajectory Memory 는 outcome 에 기반한 adaptation 을 지원한다.

  • verification failure 인 V(⋅)=falseV(\cdot)=\mathrm{false}V(⋅)=false 는 reflective backtracking 을 trigger 한다.
  • 성공적으로 validate 된 trajectory 는 향후 inference 를 accelerate 하기 위해 cache 된다.

5 Evaluation

5.1 Experimental Setup​

Benchmark and Agents​

저자는 SIREN benchmark 전체에서 experiment 를 수행한다.

  • tool stream injection case 959 개를 사용한다.
  • comprehensive baseline 으로 사용하기 위해 AgentDojo 에서 adaptation 한 data stream case 949 개를 함께 사용한다.
  • agent backbone 으로 state-of-the-art reasoning model 인 Qwen3-max 와 Gemini-2.5-pro 를 사용한다.
  • reproducibility 를 보장하기 위해 모든 model 의 temperature=0 으로 설정한다.

Baselines​

저자는 architectural paradigm 에 따라 분류되는 7 가지 representative defense mechanism 과 VIGIL 을 비교한다.

첫 번째 category 는 input-centric method 이다.

  • Spotlighting

    • delimiter-based prompt augmentation 을 사용하여 user instruction 과 untrusted data 를 구분한다.

  • DeBERTa-Classifier

    • input stream 내 malicious injection pattern 을 identify 하도록 fine-tune 된 model-based detector 이다.

두 번째 category 는 static isolation framework 이다.

  • Tool-Filter

    • initial query 에 기반하여 predefined whitelist 의 tool 로 agent 를 제한한다.

  • CaMeL

    • deviation 을 방지하기 위해 strict plan-then-execute policy 를 강제한다.

세 번째 category 는 최근 dynamic defense system 이다.

  • MELON

    • tool call 의 anomaly 를 detect 하기 위해 masked re-execution 을 사용한다.

  • DRIFT

    • interaction history 에 기반하여 security policy 를 dynamically update 한다.

마지막으로 security performance 의 lower bound 로 defense 를 적용하지 않은 Vanilla ReAct agent 를 포함한다.

Metrics​

저자는 세 가지 핵심 metric 을 report 한다.

  • Benign Utility (BU)

    • non-adversarial environment 에서의 task completion rate 를 측정한다.

  • Attack Success Rate (ASR)

    • adversary 가 malicious objective 를 성공적으로 실행한 case 의 비율을 정량화한다.

  • Utility Under Attack (UA)

    • agent 의 resilience 를 평가한다.
    • 저자는 strict criterion 을 적용한다.
    • agent 가 user task 를 완료하는 동시에 malicious instruction 을 neutralize 한 경우에만 trial 을 successful 로 간주한다.

5.2 Main Results​

Fig. 3 과 Tab. 2 에 제시된 experimental result 는 VIGIL 이 existing defense 를 제한하는 rigidity-utility trade-off 를 해결함을 보여준다.

기존 method 는 높은 vulnerability 또는 낮은 utility 중 하나에 위치하는 반면, VIGIL 은 일관되게 optimal bottom-right quadrant 에 위치한다. 이는 robust security 와 flexible reasoning 이 동시에 존재할 수 있음을 보여준다.

저자는 세 가지 핵심 metric 에 대해 performance 를 분석한다.

Attack Success Rate (ASR)​

Tab. 2 의 result 는 다음과 같다.

  • VIGIL 은 평가된 모든 model 에서 superior defense capability 를 보인다.

  • CaMeL 과 같은 static isolation framework 와 비교할 때 특히 큰 advantage 가 나타난다.

    • Qwen3-max 에서 평균 tool stream ASR 을 25% 이상에서 약 8% 로 감소시킨다.
    • Gemini-2.5-pro 에서는 약 12% 로 감소시킨다.

  • Explicit Directive 와 같은 definition-level attack 을 neutralize 하는 능력이 특히 두드러진다.

    • 이 scenario 에서 CaMeL 은 static planning 에 의존하기 때문에 context contamination 이 발생하며 ASR 이 거의 45% 에 이른다.

  • VIGIL 은 최근 dynamic defense 인 DRIFT 와 비교해서도 향상된 robustness 를 보여준다.

    • 두 backbone 모두에서 약 22~24%p 의 margin 으로 DRIFT 를 능가한다.

  • data stream baseline 에서 VIGIL 은 Tool-Filter 의 strict whitelisting 과 비슷한 수준의 매우 낮은 ASR 을 유지한다.

  • 이는 verify-before-commit mechanism 이 static isolation 의 fragility 없이 다양한 attack surface 에서 threat 를 효과적으로 neutralize 함을 보여준다.

Utility Under Attack (UA)​

Tab. 2 에서 VIGIL 의 중요한 advantage 는 static defense 가 거의 완전히 collapse 하는 adversarial environment 에서 높은 utility 를 유지한다는 점이다.

  • Tool-Filter 와 CaMeL 같은 framework 는 tool stream UA 가 12% 이하로 감소한다.

    • 이들의 rigid architecture 가 Error Hijacking 과 같은 scenario 의 deceptive runtime feedback 으로부터 recovery 하는 것을 방해하기 때문이다.

  • 반면 VIGIL 의 speculative reasoning 과 backtracking mechanism 은 이러한 static baseline 의 task completion rate 를 2 배 이상으로 증가시킨다.

  • Qwen3-max 에서는 tool stream UA 27.53% 를 달성한다.

  • VIGIL 은 overall tool stream utility 에서 가장 resilient 한 dynamic baseline 인 MELON 을 일관되게 큰 margin 으로 능가한다.

  • 이러한 reasoning flexibility 의 보존은 initial execution path 가 malicious feedback 에 의해 차단되더라도 agent 가 task 를 계속 navigate 하고 완료할 수 있음을 empirical 하게 검증한다.

Benign Utility (BU)​

VIGIL 은 최소한의 performance overhead 로 backbone model 의 native capability 에 높은 fidelity 를 유지한다.

  • Qwen3-max 에서 VIGIL 은 74.49% BU 를 달성한다.
  • 이는 undefended Vanilla ReAct agent 의 79.59% 와 근접한 수준이다.
  • 반면 CaMeL 과 DeBERTa 같은 heavy-weight defense 는 restrictive policy 때문에 BU 가 50% 이하로 크게 감소한다.
  • Gemini-2.5-pro agent 에서는 verifier 의 conservative nature 때문에 moderate performance trade-off 가 관찰된다.
  • 그럼에도 VIGIL 은 strict isolation method 를 큰 margin 으로 능가한다.

이 balance 는 underlying model 과 관계없이 substantial security gain 이 agent 의 practical usability 를 심각하게 훼손하지 않도록 한다.

5.3 Ablation Study and Sensitivity Analysis​

Ablation Study​

저자는 VIGIL 의 각 core component 가 기여하는 정도를 분리하기 위해 SIREN benchmark 에서 systematic ablation study 를 수행한다.

각각 하나의 module 을 제거한 네 가지 variant 를 평가한다.

  • Unanchored: anchor 제거
  • Unfiltered: sanitizer 제거
  • Linear: reasoner 제거
  • Unverified: verifier 제거

Tab. 3 에 제시된 것처럼, 단일 component 를 제거해도 security 또는 utility 중 하나에서 측정 가능한 degradation 이 발생한다.

  • Full System

    • Data Stream UA: 40.57
    • Data Stream ASR: 0.32
    • Tool Stream UA: 27.53
    • Tool Stream ASR: 8.13

  • Unanchored

    • Data Stream UA: 35.83
    • Data Stream ASR: 3.16
    • Tool Stream UA: 21.58
    • Tool Stream ASR: 15.33

  • Unfiltered

    • Data Stream UA: 32.67
    • Data Stream ASR: 12.33
    • Tool Stream UA: 18.56
    • Tool Stream ASR: 24.19

  • Linear

    • Data Stream UA: 39.73
    • Data Stream ASR: 0.53
    • Tool Stream UA: 9.07
    • Tool Stream ASR: 8.45

  • Unverified

    • Data Stream UA: 35.09
    • Data Stream ASR: 6.95
    • Tool Stream UA: 13.76
    • Tool Stream ASR: 45.05

특히 다음 두 결과가 두드러진다.

  • Unverified variant 는 catastrophic security failure 를 보이며 tool stream ASR 이 45.05% 까지 급증한다.
  • Linear variant 는 attack 상황의 utility 가 심각하게 collapse 하며 UA 가 27.53% 에서 9.07% 로 감소한다.

이는 robustness 와 flexibility 사이의 optimal balance 를 유지하기 위해 모든 module 이 synergistically 필요함을 보여준다.

Sensitivity Analysis​

저자는 VIGIL 의 scalability 와 robustness 를 평가하기 위해 두 가지 critical environmental variable 에 대한 sensitivity 를 분석한다.

  • toolset scale
  • attack density

먼저 scalability 를 평가하기 위해 verification overhead 가 system complexity 와 함께 linear 하게 증가하는지를 분석한다.

Fig. 4(a), Fig. 4(b) 와 관련된 experiment 는 다음과 같다.

  • 두 가지 distinct environment 에서 100 개의 sequential task 를 실행한다.
  • standard-scale setting 은 496 개 tool 을 포함한다.
  • massive-scale setting 은 co-domain utility 를 추가하여 총 3,074 개 tool 로 확장한다.
  • 각 task 에 대해 verification round 와 time cost 를 추적한다.
  • massive setting 은 expanded search space 때문에 initial verification cost 가 더 높다.
  • 하지만 두 setting 모두에서 average overhead 는 빠르게 constant level 로 converge 한다.
  • 이러한 convergence 는 Validated Trajectory Memory 가 secure execution path 를 caching 함으로써 asymptotic efficiency 를 달성함을 보여준다.

둘째, increasing adversarial pressure 에 대한 system resilience 를 조사한다.

Fig. 4(c) 와 관련된 experiment 는 다음과 같다.

  • 각 case 에서 benign tool 대비 malicious tool 의 density 를 1:1 에서 1:8 까지 점진적으로 증가시킨다.
  • highly saturated attack environment 에서도 ASR 은 일관되게 낮은 수준을 유지한다.
  • 이는 intent-grounded verifier 가 malicious candidate 의 prevalence 와 관계없이 이를 성공적으로 filtering 함을 보여준다.
  • 한편 hypothesis tree 내에서 correct tool 을 찾는 difficulty 가 증가하기 때문에 UA 는 점진적으로 감소한다.
  • 그럼에도 system 은 baseline defense 에서 흔히 나타나는 utility collapse 를 피하며 extreme hostility 상황에서도 functional capability 를 유지한다.

5.4 Further Analysis​

main benchmark comparison 을 넘어 VIGIL 을 comprehensive 하게 validate 하기 위해, 저자는 두 가지 supplementary study 를 수행한다.

첫째, cross-model generalizability 를 평가하기 위해 GPT-4o 를 agent backbone 으로 사용하여 VIGIL 을 평가한다.

이 experiment 는 verify-before-commit paradigm 이 underlying LLM 과 관계없이 consistent security gain 을 제공함을 확인한다.

둘째, alternative pre-filtering defense 로 specialized prompt injection detector 인 PIGuard 와 PromptGuard2 를 VIGIL 과 비교한다.

이 comparison 은 active intent verification 이 passive text-based classifier 의 inherent blind spot 과 over-defense tendency 를 극복함을 보여준다.

구체적인 experimental result 는 Appendix D 에 제시되어 있다.

6 Conclusion and Future Work

저자는 tool stream injection 에 대한 agentic reasoning 을 보호하기 위해 defensive paradigm 을 static isolation 에서 verify-before-commit protocol 로 전환하는 새로운 framework 인 VIGIL 을 제안했다.

SIREN benchmark 에 대한 comprehensive evaluation 을 통해, VIGIL 이 sophisticated attack 을 neutralize 하면서 높은 reasoning utility 를 보존하여 existing defense 를 크게 능가함을 보여주었다.

이 연구는 speculative exploration 과 irreversible execution 을 분리하는 것이 open environment 에 trustworthy agent 를 deployment 하기 위한 효과적인 methodology 임을 확립한다.

향후 연구에서는 다음과 같은 방향으로 이 연구를 확장할 수 있다.

  • advanced pruning strategy 를 통해 speculative reasoner 의 computational efficiency 를 향상할 수 있다.
  • verify-before-commit paradigm 을 multi-modal agent 로 확장하여 visual interface 내에서 새롭게 등장하는 injection surface 를 처리할 수 있다.
  • VIGIL 을 training-based alignment technique 와 통합하여 evolving cognitive threat 에 대응하는 comprehensive defense-in-depth architecture 를 구성할 수 있다.
